# pascal_house — MARB-A architecture lane (PH-1 "Bungalow")

The first task of the **architecture lane**: an AI model drives the
[Pascal](https://github.com/pascalorg/editor) 3D building editor headlessly
through `@pascal-app/mcp` to realize a fully specified single-story house from
a text program, then submits the `export_json` scene. This suits Pascal's
native input mechanism (natural-language brief -> MCP scene tools) instead of
forcing it through the mechanical board's STEP path.

## Files

- `ph1_reference_layout.yaml` — the **answer key** (walls, openings,
  furnishings, tolerances, BOM). Never bundle into a blind kit.
- `ph1_reference_scene.json` — the answer key realized as a Pascal-shaped
  scene, generated by `pascal_scene_grade.py --emit-ref-scene`. Used by the
  grader self-test.

Both key files are gitignored and absent from a fresh clone — see
[ANSWER_KEY.md](ANSWER_KEY.md) for how to obtain them and for the sha256
digests that pin the exact revision the published grades used.

The blind kit lives at `kits/pascal_house_blind_kit_v0.1/` (task brief, goal
floorplan render, catalog manifest).

## Run-folder convention

Every sealed-run folder is named `ph1_<model><ver>_<effort>_<n>` (e.g.
`ph1_opus48_max_01`, `ph1_fable5_high_01`) so the cohort is readable from the
artifact path. Each folder contains the extracted blind kit, a `.mcp.json`
pointing `PASCAL_DATA_DIR` inside the folder, and `.claude/settings.json`
pinning `model` (+ `effortLevel` when it isn't `max` — `max` is session-only
and must be passed as `--effort max` at launch). Launch with explicit flags
anyway (`claude --model opus --effort max`); flags override settings, so the
folder name, settings pin, and flags can never disagree silently. Name the
grades file to match: `results/pascal_ph1_<model>_<effort>_<n>.json`.

## Grade a run

```bash
py -3.11 grader/pascal_scene_grade.py \
    --ref tasks/pascal_house/ph1_reference_layout.yaml \
    --scene run_scene.json --json results/pascal_grades.json

# sanity: reference against itself must be all-zeros / all-pass
py -3.11 grader/pascal_scene_grade.py \
    --ref tasks/pascal_house/ph1_reference_layout.yaml --self-test
```

Metrics (architecture-lane analogs of the mechanical board):

| Metric | Meaning | Mechanical analog |
|---|---|---|
| WALL | median wall-centerline midpoint error (mm) | POS (structure) |
| OPEN | median door/window center error (mm) | GAP (interfaces) |
| POS-A | median furnishing placement error (mm) | POS |
| ORIENT-A | % asymmetric furnishings with correct yaw (±15°, mod symmetry) | ORIENT |

Gates: BOM match, item-item AABB collisions (must be 0), envelope. Room
connectivity is `not_gated` in v0.1.

## Pipeline validation (2026-07-08)

`smoke_build_via_mcp.py` (answer-key-side harness — never give to a blind
run) drove the real published `@pascal-app/mcp` 0.3.1 server over stdio,
built PH-1 via `create_wall`/`add_door`/`add_window`/`place_item`, exported
with `export_json`, and the grader scored it 0.0 mm on every metric, 100%
ORIENT-A, all gates PASS. This validates units, coordinate frames, door
`t`-placement round-tripping, and that Pascal stores placements without
snapping. Pascal's own `check_collisions` reported 2 false positives on
rotated furniture (its AABB ignores yaw — `packages/mcp/src/tools/`
`check-collisions.ts` uses unrotated `getScaledDimensions`); the task brief
warns drivers accordingly, and the MARB-A gate (yaw-snapped AABB) is the
scored one.

## Rendering a run in the real Pascal editor (hero images)

Pascal's 3D renderer is browser-only, but a run scene can be rendered
headlessly for post artifacts:

1. In the pascal-editor repo clone: `bun install`, `bunx turbo run build
   --filter='./packages/*'` (the editor's API imports built workspace
   packages), `touch .env.local`, then `cd apps/editor && bun run dev`
   (port 3002).
2. `POST http://localhost:3002/api/scenes` with `{name, graph: {nodes,
   rootNodeIds}}` from the run's `run_scene.json` (loopback requests skip
   auth). The response id serves at `/scene/<id>` — note the returned
   `editorUrl` (`/editor/...`) is the hosted app's route, not the local one.
3. Screenshot with Playwright: wait ~40 s for GLB loads under swiftshader,
   mouse-wheel to frame, hide non-canvas DOM, capture the canvas region,
   crop to 1.91:1. Example script used for run 01 is preserved in the
   session scratchpad (`shot/hero.js`); output:
   `results/figures/pascal_ph1_fable5_medium_01_hero3d.png`.

## Known v0.1 limits

- **Yaw front calibration.** Reference yaws assume the three.js convention
  (yaw 0 = asset front toward +Z, front = (sin y, cos y)). Pascal's shipped
  GLB fronts have not been visually calibrated; the reference carries a
  per-asset `yaw_offset_deg` table to absorb any constant offsets after one
  pass in the browser editor. Until then, treat ORIENT-A across *tools* with
  caution; within-lane comparisons are unaffected.
- Collision gate is yaw-snapped AABB, not mesh-accurate.
- Wall-attached and ceiling-attached items are excluded from the program.
- Single level only; no roof, stairs, materials, or landscaping.
- Not comparable with the M3-CRETE mechanical board — different lane,
  different kit cohort. Report as "Pascal MCP scene-authoring evaluation"
  per `analysis/pascal-editor/pascal_editor_marb_fit.md`.
